# 方法改进型项目汇报示例

这是通用编排示例，不包含客户数据，不假定某种算法已经取得实验优势。实际使用时按项目要求替换。

## 情境

项目需要在原有业务方法上引入智能修正、适应新的部署环境并提高准确性。听众第一次接触方案，希望理解改动、依据、实际效果与应用价值。

## 按听众的问题编排

1. 业务与目标：说清方法位于哪项业务中、本次解决什么问题、怎样判断完成。
2. 总体方案：输入较小、模型主体清楚、输出明确，运行箭头连续。
3. 新旧对照：同层级并排原流程与新流程，标出替换与新增模块。
4. 原理与依据：用任务特征、方法原理、同行实践说明选择，再回到同一总图。
5. 评价标准：先交代参照对象、比较尺度、精度指标和一次真实业务总用时。
6. 整体证据：先整体结果，再局部放大与机制呼应，随后量化对比。
7. 典型案例：使用同一模板展示真实案例、相同指标和改善幅度。
8. 总结：逐项回答最初需求，说明成果与应用安排。

## 避免混淆

“总—分—总”分别用于认清组成、理解原理、整合方法，避免重复讲同一流程。

理论及同行应用说明为什么采用，项目实验回答实际表现。若结果不支持预期，应核对并调整结论。

有训练环节时，明确已训练模型如何交给应用环节；区分输入数据、模型、推理输出与最终成果。

## 版式与深度

目录干净，总图展示全貌，原理聚焦关键机制，同类案例固定图、指标和结论的位置。技术深度以项目判断所需为限，没有页数上限也不机械拆页。
